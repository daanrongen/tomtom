# tomtom

A Unix-friendly CLI for [TomTom](https://developer.tomtom.com/)'s location APIs — search, geocoding, routing, traffic, and a raw escape hatch for everything else — built with [Bun](https://bun.sh) and [Effect](https://effect.website).

## Install

```sh
brew tap daanrongen/tomtom
brew install tomtom
```

Installs a standalone binary (no Bun runtime required) — prebuilt for macOS and Linux, arm64 and x64. Verify with:

```sh
tomtom --version
```

Or from source:

```sh
git clone https://github.com/daanrongen/tomtom.git
cd tomtom
bun install
bun run build   # produces ./dist/tomtom
```

## Authentication

```sh
export TOMTOM_API_KEY="..."
```

or persist it:

```sh
tomtom config set api-key <key>
tomtom config test   # verifies the key against a real endpoint
```

Precedence: `--api-key` > `TOMTOM_API_KEY` > the config file (`tomtom config path`).

## Usage

```sh
tomtom search "Heathrow Airport"
tomtom search nearby --lat 51.5074 --lon -0.1278 --radius 2000 --category 7315   # 7315 = restaurants
tomtom search category 7315 --lat 51.5074 --lon -0.1278 --radius 2000
tomtom search brand Starbucks --lat 51.5074 --lon -0.1278 --radius 2000
tomtom geocode "10 Downing Street, London"
tomtom reverse-geocode 51.5034,-0.1276
tomtom route calculate --from London --to Oxford --traffic
tomtom route reachable-range --from London --time 1800 --json > london-30min.json
tomtom route matrix --input matrix.json
tomtom traffic incidents --bbox "-0.2,51.45,-0.05,51.55"
tomtom traffic flow segment --point 51.5074,-0.1278 --style relative --zoom 10
tomtom traffic flow tile --style relative --zoom 10 --tile-x 511 --tile-y 340 --output flow-tile.png
tomtom map static --center 51.5074,-0.1278 --zoom 12 --output map.png
tomtom map tile --layer basic --style main --zoom 10 --tile-x 511 --tile-y 340 --output tile.png
tomtom api request --method GET --url "https://api.tomtom.com/search/2/geocode/London.json"
tomtom search fuzzy coffee --lat 51.5074 --lon -0.1278 --select 'results[].position'   # jq-lite selector
tomtom route reachable-range --from London --time 1800 --geojson > london-30min.geojson
tomtom schema search        # JSON Schema for a command's output shape
tomtom agent-info           # machine-readable capability manifest
tomtom skill > ~/.claude/skills/tomtom/SKILL.md   # install/refresh this CLI as a Claude Code skill
```

Every command supports `--json` (unmodified TomTom response body, stable for `jq`), `--pretty`, `--api-key`, `--timeout`, `--retry`/`--no-retry`, `--debug`, and `--select <path>` (a jq-lite selector, e.g. `results[].position`, applied before output). With `--json`/`--pretty`, a failed command reports a structured `{"error": {...}}` object instead of plain text. Shell completion is generated by `@effect/cli`:

```sh
tomtom --completions zsh > "${fpath[1]}/_tomtom"
```

`route matrix` takes a JSON file of `origins`/`destinations` arrays, each entry a `"lat,lon"` string, a free-text place name, or `{"lat": .., "lon": ..}`:

```json
{ "origins": [{ "lat": 51.5074, "lon": -0.1278 }], "destinations": ["Oxford", "52.2053,0.1218"] }
```

`map static`/`map tile`/`traffic flow tile`'s output is raw image bytes, not JSON — `--json`/`--pretty` don't apply to them; use `--output <path>` to write to a file, or omit it (or pass `--output -`) to write to stdout.

## Scope

This tool covers what a standard TomTom API key can reach: the classic Search, Geocoding, Routing, Traffic, and Map Display APIs. It intentionally does not cover TomTom's Orbis Maps platform (extended search along-route/geometry, EV routing/search, data visualization) — those require a separately provisioned Orbis API key/project, so they're out of scope here.

## Architecture

Domain-driven, ports & adapters:

```
src/
  domain/        pure types and validation (Coordinate, BoundingBox, error ADTs) — no IO
  ports/         driven-side interfaces as Effect Context.Tags (TomTomClient, ConfigStore)
  adapters/      implementations of those ports (HTTP client with retry/backoff, TOML config file)
  application/   use cases that orchestrate ports (GeocodeService, RouteService, ...)
  cli/           the @effect/cli command tree — the composition root
```

Only genuine external-system boundaries are ports (HTTP, the config file); output formatting is plain functions plus Effect's `Console`.

## Development

```sh
bun install
bun run dev -- geocode "London" --json   # run from source
bun run typecheck
bun test test/unit                        # unit tests, no network
bun test test/integration                 # opt-in, needs a real TOMTOM_API_KEY
bun run build                             # bun build --compile -> ./dist/tomtom
```

[Biome](https://biomejs.dev) handles formatting and linting; [Lefthook](https://lefthook.dev) runs it on every commit and runs the test suite plus a build before every push:

```sh
lefthook install   # one-time, per clone
```

## Release process

Pushing a `vX.Y.Z` tag (matching the version in `package.json`) runs the full pipeline: tests → cross-compiled binaries for macOS/Linux, arm64/x64 → a GitHub Release with those binaries attached → an updated `Formula/tomtom.rb` pushed to the [`homebrew-tomtom`](https://github.com/daanrongen/homebrew-tomtom) tap. See `.github/workflows/release.yml`.
