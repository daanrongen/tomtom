# tomtom

A Unix-friendly CLI for [TomTom](https://developer.tomtom.com/)'s location APIs — search, geocoding, routing, traffic, and a raw escape hatch for everything else — built with [Bun](https://bun.sh) and [Effect](https://effect.website).

## Install

```sh
brew tap daanrongen/tomtom
brew install tomtom
```

Or from source:

```sh
git clone https://github.com/daanrongen/tomtom.git
cd tomtom
bun install
bun run build   # produces ./dist/tomtom
```

## Authentication

```sh
export TOMTOM_API_KEY="..."
```

or persist it:

```sh
tomtom config set api-key <key>
tomtom config test   # verifies the key against a real endpoint
```

Precedence: `--api-key` > `TOMTOM_API_KEY` > the config file (`tomtom config path`).

## Usage

```sh
tomtom search "Heathrow Airport"
tomtom search nearby --lat 51.5074 --lon -0.1278 --radius 2000 --category restaurant
tomtom geocode "10 Downing Street, London"
tomtom reverse-geocode 51.5034,-0.1276
tomtom route calculate --from London --to Oxford --traffic
tomtom route reachable-range --from London --time 1800 --json > london-30min.json
tomtom traffic incidents --bbox "-0.2,51.45,-0.05,51.55"
tomtom api request --method GET --url "https://api.tomtom.com/search/2/geocode/London.json"
```

Every command supports `--json` (unmodified TomTom response body, stable for `jq`), `--pretty`, `--api-key`, `--timeout`, `--retry`/`--no-retry`, `--debug`, and `--backend tomtom-maps|tomtom-orbis-maps`. Shell completion is generated by `@effect/cli`:

```sh
tomtom --completions zsh > "${fpath[1]}/_tomtom"
```

Commands not yet implemented (route matrix, EV routing/search, map static/tile, data-viz, search along-route/geometry/ev, traffic flow) are wired into the tree and show up in `--help`, but exit with a clear "not implemented" error — see [Roadmap](#roadmap).

## Architecture

Domain-driven, ports & adapters:

```
src/
  domain/        pure types and validation (Coordinate, BoundingBox, error ADTs) — no IO
  ports/         driven-side interfaces as Effect Context.Tags (TomTomClient, ConfigStore)
  adapters/      implementations of those ports (HTTP client with retry/backoff, TOML config file)
  application/   use cases that orchestrate ports (GeocodeService, RouteService, ...)
  cli/           the @effect/cli command tree — the composition root
```

Only genuine external-system boundaries are ports (HTTP, the config file); output formatting is plain functions plus Effect's `Console`.

## Development

```sh
bun install
bun run dev -- geocode "London" --json   # run from source
bun run typecheck
bun test test/unit                        # unit tests, no network
bun test test/integration                 # opt-in, needs a real TOMTOM_API_KEY
bun run build                             # bun build --compile -> ./dist/tomtom
```

[Biome](https://biomejs.dev) handles formatting and linting; [Lefthook](https://lefthook.dev) runs it on every commit and runs the test suite plus a build before every push:

```sh
lefthook install   # one-time, per clone
```

## Release process

Pushing a `vX.Y.Z` tag (matching the version in `package.json`) runs the full pipeline: tests → cross-compiled binaries for macOS/Linux, arm64/x64 → a GitHub Release with those binaries attached → an updated `Formula/tomtom.rb` pushed to the [`homebrew-tomtom`](https://github.com/daanrongen/homebrew-tomtom) tap. See `.github/workflows/release.yml`.

## Roadmap

Phase 1 (this release): config, search (fuzzy/poi/nearby), geocode, reverse-geocode, route calculate, reachable-range, traffic incidents/details, the `api request` escape hatch, shell completion.

Phase 2+: route matrix, search category/brand/geometry/along-route/ev, traffic flow, map static/tile, EV routing/search, data-viz — see the TomTom API spec this project was built from for full scope.
